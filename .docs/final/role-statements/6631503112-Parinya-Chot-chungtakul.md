# Parinya Chotchungtakul — QA/Test

## What I owned

I was responsible for testing the JoinGun system and conducting user evaluation. My QA work included checking implemented flows against the test plan, recording defects, and validating system behavior. On the technical side, the repository includes the [test plan](../../03-testing/test-plan.md) and [browser end-to-end tests](../../../tests/e2e/core-journey.spec.js), reporting 47/47 API and database integration checks and 6/6 browser checks passing as of 2026-10-28.

For user testing, my verified work centers on the **Informal / Ad hoc Usability Testing** (testing with real users, done informally with no systematic steps or controls), which has full documented evidence in the repository. I conducted this evaluation with 16 real users tested informally (`U01–U16`), measuring core workflow tasks (Scenario Set B), usability (SUS mean 57.66), technology acceptance (TAM: PU 4.08, PEOU 3.97, BI 3.81, Perceived Safety 3.66), and paired overall satisfaction (`n = 10`). This informal testing is completed, and its data has been entered into the project's primary UAT document, [JoinGun - Testing.xlsx](../../03-testing/JoinGun%20-%20Testing.xlsx) (along with the raw survey workbook [JoinGun — แบบสอบถาม SUS และ TAM (Responses).xlsx](../../03-testing/JoinGun%20%E2%80%94%20%E0%B9%81%E0%B8%9A%E0%B8%9A%E0%B8%AA%E0%B8%AD%E0%B8%9A%E0%B8%96%E0%B8%B2%E0%B8%A1%20SUS%20%E0%B9%81%E0%B8%A5%E0%B8%B0%20TAM%20%28Responses%29.xlsx) and the [testing summary](../../03-testing/no-real-user-test.md)). Note that the separate template file `uat-record.xlsx` holds no recorded data; all empirical UAT records reside in `JoinGun - Testing.xlsx`.

In contrast, formal UAT (moderated, controlled sessions) on a deployed HTTPS environment has not yet been completed and currently has no recorded evidence. If formal UAT is conducted, the session dates, testing methodology, participant count and anonymized participant codes/IDs, and empirical results must first be recorded as evidence before any claim or reference to that testing can be made. My role statement therefore explicitly refers to the completed informal usability testing as the substantiated user evidence to date.

## Reflection

### 1. Lessons learned

Building Join Gun with AI made our work faster and easier. AI helped with design, coding, and testing. I could turn ideas in my head into prompts and let AI produce the design or code, and it checked my work and found bugs for me, so I did not have to hunt for them myself. This was the biggest improvement.

However, some things got worse. If I rely on AI alone, I may not understand why the code is structured the way it is, which weakens my grasp of architecture and security. Teamwork can also suffer, because each person works with their own AI and the team talks less. To avoid this, we should divide responsibilities clearly so everyone can work with AI without overlapping.

### 2. Where I stand in the AI era

In the AI era, I see myself as a prompt engineer: I give AI clear instructions, and it carries them out. My strength is that today's AI is already very capable, so a good prompt can achieve a lot. What I still need to develop is skill. I need to learn how to define the process and structure for AI first, so it understands the context before it starts working. I also need to study the different features and skills of AI tools properly, because they are very useful once I can use them confidently.

### 3. My plan

Next year, I will do my internship. My goal is to gain as much knowledge and real experience as I can from the work, including how to work well in a team. In five years, I want to be a prompt engineer working in fullstack development, able to direct AI while understanding the systems I build.
