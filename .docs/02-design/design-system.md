# JoinGun — Design System

ใช้กับ core workflow **“เข้าร่วมกิจกรรมจากฟีด”** ใน [user-journey.md](user-journey.md) และใช้กฎเดียวกันเมื่อเพิ่มหน้าจออื่น เป้าหมายคืออ่านง่ายบนมือถือ เห็นเวลาและจุดนัดหมายชัด และกดเข้าร่วมได้สะดวก

เอกสารต้นทางไม่มีภาพ UI หรือสีแบรนด์ JoinGun: tokens ด้านล่างเป็นข้อเสนอการออกแบบสำหรับเวอร์ชันแรก ไม่ใช่ค่าที่ดึงจากเอกสารเดิม

## Layout และการอ่าน

- เริ่มออกแบบที่จอกว้าง 360px และให้ใช้งานได้ที่ 320px โดยไม่เลื่อนแนวนอน: เนื้อหาหนึ่งคอลัมน์ กว้าง 100% ไม่เกิน `layout-content-max` และเว้นขอบ `space-4`
- ตั้งแต่ `breakpoint-wide` ให้จัดกรอบเนื้อหากึ่งกลางจอและเว้นพื้นที่รอบ `space-6` โดยรักษาลำดับขั้นและปุ่มเดิม
- ใช้ชื่อหน้าจอหนึ่งหัวข้อหลักต่อหน้า ข้อความชิดซ้าย; ชื่อกิจกรรมและข้อมูลวันเวลา/สถานที่ต้องขึ้นบรรทัดใหม่ได้ ไม่ตัดข้อมูลสำคัญด้วยจุดไข่ปลา
- แถบปุ่มด้านล่างต้องเผื่อ `env(safe-area-inset-bottom)` และเว้นพื้นที่ท้ายเนื้อหาเท่าความสูงแถบจริงรวม `space-4` เพื่อไม่บังข้อมูลหรือ focus เมื่อเปิดคีย์บอร์ด
- ใช้วันที่และเวลาแบบเดียวกันทุกหน้า เช่น “8 ก.ย. 2569 · 17:00 น.” แสดงเวลาท้องถิ่นมหาวิทยาลัย (`Asia/Bangkok`)

## Component rules

| Component | กฎที่ต้องใช้ทุกหน้า |
| --- | --- |
| ปุ่ม | สูงอย่างน้อย `size-control`, padding แนวนอน `space-6`, มุม `radius-pill` (ทรงแคปซูลตามเลย์เอาต์อ้างอิงแบบ X); ปุ่มหลักพื้น primary/ข้อความ on-primary และกว้างเต็มพื้นที่บนมือถือ มีปุ่มหลักเด่นหนึ่งปุ่มต่อหน้าหรือแผงที่กำลังใช้งาน |
| ปุ่มรองและไอคอน | ปุ่มรองพื้น surface ขอบ control-border ข้อความ primary; เว้นจากปุ่มอื่นอย่างน้อย `space-2`; ปุ่มไอคอนมีพื้นที่กดอย่างน้อย `size-touch-min` และชื่อที่โปรแกรมอ่านหน้าจออ่านได้ |
| การ์ดกิจกรรม | พื้น surface ขอบ border มุม card padding `space-4` ช่องว่างระหว่างการ์ด `space-3`; เรียงชื่อ → หมวด → วันเวลา → สถานที่ → จำนวนคน เช่น “4/8 คน” → ปุ่มรอง “ดูรายละเอียด” ห้ามเข้าร่วมทันทีจากการ์ด |
| ตัวกรอง | ปุ่ม “ตัวกรอง” เปิดแผงเลือกหมวดและวันที่ มี label ทุกช่องและปุ่มหลัก “แสดงกิจกรรม”; chip สูงอย่างน้อย touch-min ใช้ primary-soft พร้อมเครื่องหมายเลือกและข้อความเมื่อ active และห่อบรรทัดได้ |
| ช่องกรอก | สูงอย่างน้อย control ใช้ body มี label อยู่เหนือช่องตลอดเวลา; placeholder เป็นเพียงตัวอย่าง ข้อความช่วยเหลือห่าง `space-1`; checkbox และ label กดได้ทั้งแถวสูงอย่างน้อย touch-min |
| รายละเอียดกิจกรรม | แสดงชื่อ รายละเอียด ผู้จัด วันเวลา จำนวนคนและที่ว่าง ก่อนแผนที่; แสดงชื่อสถานที่และคำอธิบายจุดนัดหมายเป็นข้อความด้วยเสมอ ไม่ใช้แผนที่เป็นข้อมูลเพียงอย่างเดียว |
| แผนที่ | เต็มความกว้างกรอบ สูงอย่างน้อย size-map-min มุม card แสดงหมุดของผู้จัด; การดูจุดนัดหมายไม่ร้องขอ GPS ของผู้ชม และไม่แสดงระยะทางจากผู้ชมเมื่อไม่มีข้อมูลตำแหน่งที่ได้รับอนุญาต |
| ป้ายสถานะ | ใช้ caption และ pill; “ยืนยันอีเมลสถานศึกษาแล้ว” ใช้ primary-soft ส่วน “เข้าร่วมแล้ว” ใช้ success-soft/success พร้อมไอคอนและข้อความ ห้ามสื่อว่าเป็นการรับประกันตัวตนหรือความปลอดภัย |
| แผงยืนยัน | มือถือเปิดจากด้านล่าง จอใหญ่แสดง dialog กึ่งกลางไม่เกิน content-max; พื้น surface padding `space-4` มุม card มีหัวข้อ สรุปนัดหมาย consent และปุ่ม “ยืนยันเข้าร่วม”; เนื้อหายาวต้องเลื่อนได้ |
| ข้อความสำเร็จ | ใช้ success-soft/success พร้อมข้อความ “เข้าร่วมสำเร็จ” และสรุปนัดหมายที่คงอยู่บนหน้าจอ มีปุ่มหลัก “ดูรายละเอียดกิจกรรม”; ไม่ใช้ toast ที่หายไปเป็นหลักฐานสำเร็จเพียงอย่างเดียว |

## ความยินยอมและข้อความใน UI

- ตาม LR1 และกฎโครงการ ให้แสดงวัตถุประสงค์การเก็บประวัติในแผงยืนยันก่อนบันทึกการเข้าร่วม ใช้ checkbox เริ่มต้นว่างและลิงก์นโยบายความเป็นส่วนตัวที่เปิดอ่านได้ ปุ่มยืนยันใช้ได้เมื่อมีความยินยอมที่ใช้ได้
- หากเคยให้ความยินยอมที่ใช้ได้แล้ว ให้แสดงข้อความสถานะและทางเข้าจัดการความยินยอมแทนการขอซ้ำ ไม่ผูกความยินยอมประวัติเข้ากับ GPS หรือ AI recommendation
- แผงต้องมีปุ่มรอง “กลับไปดูกิจกรรม” ให้ปิดได้โดยยังไม่เข้าร่วม; หากพัฒนา “ใช้ตำแหน่งปัจจุบัน” ในภายหลัง ต้องขอความยินยอมตำแหน่งแยกเมื่อผู้ใช้เลือกใช้เท่านั้น
- ใต้ข้อมูลผู้จัดแสดงคำแนะนำสั้น ๆ “นัดพบในพื้นที่สาธารณะ และตรวจสอบรายละเอียดก่อนเข้าร่วม” ตามกฎความปลอดภัยของโครงการ
- ใช้ชื่อหน้าจอ ปุ่ม และสถานะตาม user journey ทุกจุด; ไม่นำศัพท์ฐานข้อมูล ระบบบันทึก log หรือ API มาเป็นข้อความในขั้นตอนใช้งาน

## สถานะและ accessibility

- ทุกปุ่มต้องมี default, pressed, focus-visible, disabled และ loading; ขณะส่งคำขอใช้ “กำลังเข้าร่วม…” ปิดการกดซ้ำ และแสดงสำเร็จเมื่อระบบยืนยันผลแล้วเท่านั้น
- เมื่อเข้าร่วมแล้ว แสดงสถานะ “เข้าร่วมแล้ว” แทนปุ่มเข้าร่วม; การออกจากกิจกรรมตาม Backlog 2.4 ใช้ปุ่มรองแยกเมื่อพัฒนาส่วนนั้น
- ข้อผิดพลาดใช้ข้อความระบุปัญหาคู่กับสี danger; ฟีดกำลังโหลดใช้ skeleton ขนาดใกล้การ์ดจริง ฟีดว่างมีข้อความและปุ่ม “ล้างตัวกรอง” สถานะเหล่านี้เป็นกฎ component และไม่เพิ่มขั้นตอนใน happy path
- ข้อความปกติต้องมี contrast อย่างน้อย 4.5:1 และขอบ control/ตัวบ่งชี้สถานะอย่างน้อย 3:1 กับพื้นหลัง; ห้ามใช้สีอย่างเดียวสื่อความหมาย
- รองรับขยายข้อความ 200% โดยไม่ซ้อนหรือตัดเนื้อหา ใช้ปุ่มและช่องกรอกแบบ semantic พร้อม label; ปุ่มที่ disabled ต้องมีคำอธิบายเหตุผลใกล้กัน
- เมื่อเปิด dialog ให้ย้าย focus เข้าแผง จำกัด focus ภายใน และคืน focus ที่ปุ่มเดิมเมื่อปิด รองรับ Escape และประกาศผลการเข้าร่วมให้โปรแกรมอ่านหน้าจอ
- เมื่อผู้ใช้ตั้งค่า reduced motion ให้ปิด animation ที่ไม่จำเป็น

## บัญชีผู้ใช้: หน้าต้อนรับและการสมัคร

ใช้ลำดับการใช้งานและเลย์เอาต์ของ X เป็นต้นแบบ แต่ใช้ token ของ JoinGun ทั้งหมด ไม่ใช้โลโก้ สี หรือข้อความของ X

| Component | กฎ |
| --- | --- |
| หน้าต้อนรับ | ผู้ที่ยังไม่เข้าสู่ระบบเห็นหน้านี้เป็นหน้าแรก มือถือเรียงหัวข้อ `text-display` → คำอธิบาย → ปุ่มหลัก “สมัครด้วยอีเมลสถานศึกษา” → หัวข้อ “มีบัญชีอยู่แล้ว?” → ปุ่มขอบ “เข้าสู่ระบบ” → ลิงก์ “ดูกิจกรรมก่อน”; ตั้งแต่ `breakpoint-wide` ให้แสดงสัญลักษณ์ J ขนาดใหญ่ด้านซ้ายและปุ่มด้านขวา |
| แผงสมัคร/เข้าสู่ระบบ | หนึ่งคำถามต่อหนึ่งขั้น มีปุ่มปิดหรือย้อนกลับมุมซ้ายบน สัญลักษณ์ J กลางด้านบน และป้าย “ขั้นตอนที่ n จาก 4” ระหว่างสมัคร: อีเมล → รหัส 6 หลัก → ยอมรับข้อตกลง → ตั้งโปรไฟล์ การเข้าสู่ระบบใช้แค่อีเมลกับรหัส ถ้าอีเมลยังไม่มีบัญชีให้ไปขั้นยอมรับข้อตกลงต่อ |
| ยอมรับข้อตกลง | สรุปข้อมูลที่เก็บและไม่เก็บ ลิงก์อ่านฉบับเต็ม และ checkbox ที่ผู้ใช้ติ๊กเองพร้อมเลขเวอร์ชัน ห้ามใช้ข้อความแบบ “การสมัครถือว่ายอมรับ” เพราะ rule.md ต้องการหลักฐานการกดยอมรับ ไม่รวมความยินยอมประวัติการเข้าร่วมหรือตำแหน่งไว้ในขั้นนี้ |
| ตั้งโปรไฟล์ | ชื่อที่แสดงและชื่อผู้ใช้ (@ 3–20 ตัว a–z 0–9 _) บังคับ ชั้นปีและความสนใจไม่บังคับ ไม่มีช่องข้อมูลอื่นตาม LR5 |
| เมนูบัญชี | มุมขวาบนแสดงปุ่ม “เข้าสู่ระบบ” และ “สมัคร” เมื่อยังไม่เข้าสู่ระบบ และรูปย่อเมื่อเข้าสู่ระบบแล้ว กดแล้วเปิดเมนูที่มีชื่อ @ชื่อผู้ใช้ และ “ออกจากระบบ” |
| การกระทำที่ต้องมีบัญชี | เช่นสร้างโพสต์ ให้เปิดแผงเข้าสู่ระบบพร้อมบอกเหตุผล แล้วทำต่อให้อัตโนมัติหลังเข้าสู่ระบบสำเร็จ |
